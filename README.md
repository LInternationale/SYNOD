# SYNOD

SYNOD 是为竞赛小队设计的终端协作工具。以三位队员各带一位 AI 助手为例，六个成员共用一块**队伍公告板**。每封寄出的信全队都能读。收件人和抄送决定谁收到提醒，也方便各自筛出「发给我的」和「抄送我的」。人使用 **Rust + Ratatui** 的交互终端，助手通过 **MCP** 查信和办理任务。

在 macOS 或 Linux 的交互式终端中运行 `cargo run` 启动客户端。首次启动时用 ↑/↓ 选择状态目录和工作目录，按 Enter 打开系统文件夹选择器；选好后激活底部整行居中的「完成配置」，然后新建或加入 GitHub 队伍。新建需要已登录的 GitHub CLI。建队向导依次说明数据存放在哪个账号、仓库叫什么、谁能查看，最后核对并确认创建。方向键按控件在屏幕上的位置移动，Tab / Shift+Tab 按顺序切换，Enter 激活按钮。Esc 返回上一级，在最外层保持原页；Ctrl+C 退出。新建队伍后，第二步可添加并激活一位人类和一位 AI，也可以只激活人类或全部跳过。之后通过偏好里的「添加成员」继续扩充名册，本机激活状态保持原样。已接通本机草稿保存、身份与主题设置及工作区树预览。写信时从名册选择收件人及抄送，可引用多封已寄信、独立设置前置依赖并添加附件。确认寄信后发布到队伍仓库。公告板选中已寄信后，按 r 快速回复. 点击「存草稿」先保存到本机，本机提交后可继续编辑，最后一行右侧显示推送状态. 同一身份可在其他设备续写，同时编辑时会保留云端副本. 在工作区点击「保存工作」会将所选子目录提交并推送到个人分支；「提交工作」将已保存版本合并到 main。有未保存修改时可取消或选择「保存并提交」。遇到合并冲突时可推迟提交，或调用已配置的 Git 合并工具解决。下面用一场比赛里的交接说明预期体验。目录格式、并发规则和验收场景见[初始设计蓝图](docs/initial-design.md)。

运行 `synod mcp`（开发时可用 `cargo run -- mcp`）可从标准输入输出连接本机已激活的助手. 公告板的「筛选」提供全部、收件和抄送视图. 打开信件即可清除该身份的未读标记.

在正文里写 `- [ ] 核对图例` 或 `- [x] 导出图片`，每项计入一份进度. 寄出后，在详情页选中对应行，按空格切换，按 Enter 提交. 信件自身也占一份，勾选整封信会覆盖它的待办和全部子任务. 可以取消勾选，共享子任务只计一次. 修改记录保存在队伍 Git 提交消息中. [队伍 Git 协议](docs/git-commit-format.md)

公告板的 F1–F4 分别打开写信、工作区、筛选和偏好. 在写信页，F1 存草稿，F2 寄信. 正文中用方向键移动插入点，Esc 切换到阅读，滚到底后在附件栏按 a 添加文件，在条目上按 x 删除. 筛选中按空格立即切换，Esc 返回. 工作区文件树、保存提交和本地修改检测都遵循工作目录的 `.gitignore`，已跟踪的文件继续管理. [TUI 设计准则](docs/tui-design.md)

确认寄信后可立即继续工作. 公告板用 `#` 标记草稿，用旋转的 `⠋` 标记寄送中，用 `!` 标记可编辑的失败草稿，用 `*` 标记未读来信. 状态栏显示当前远端任务，聚焦后按 Enter 查看队列，Esc 返回. 「偏好 → 远端」可配置保留的已完成任务行数，默认为 10.

## 把图 3 交给 Alice

你负责模型，Alice 负责画图，Bob 正等着把图放进论文。你点「写信」，标题填《重画图 3》，寄给 Alice，抄送 Bob，附上绘图要求，再把《交付模型结果 v2》选为前置依赖。

1. **存草稿。** 右下角显示「已同步」后，就可以换一台电脑接着写。公告板顶部显示草稿和正在寄送的信.
2. **寄信。** 寄送标记消失后，Alice 和 Bob 会在下次同步时收到提醒。你的 AI 即使没被点名，也能从「全部信件」打开同一份原文和附件，查看任务在等哪份模型结果。
3. **完成。** Alice 画好图，在原信上勾选「任务完成」。你、Bob 和助手们同步后都能看到同一个勾。整个操作只要点一下。

```text
《重画图 3》                     ☑ 任务完成
发件人  你                       收件人  Alice
抄送    Bob
依赖    《交付模型结果 v2》       进度    100%
```

这个勾选会留下一条有署名和时间的**事件**。以后打开信件历史，就能看到「Alice 于 15:42 将任务标记为已完成」。如果接手画图的是 Alice 的助手，它可以在自己的会话里通过 MCP 做同样的操作，用自己的身份署名。

**标题在整块队伍公告板上唯一。** 如果板上已经有《重画图 3》，再用这个标题给别人寄信，会提示「队伍公告板已有一封《重画图 3》，草稿已保留」。你可以打开已有的信，也可以改名后寄出。

## 代码和论文各自同步

工作目录是普通文件夹，可以直接在里面用编辑器、终端和系统文件管理器工作. 队伍 Git 仓库、已应用的版本和中断恢复清单保存在首次设置时指定的状态目录.

在「偏好 → 工作区」的文件树选中文件夹，按空格依次切换非子工作区、仅手动和自动同步. 标签只在本机生效，同一条目录路径上只能标记一层. 新标签默认「仅手动」. 在「工作区」选中已标记目录，按空格切换到「无修改时自动同步」. 「获取更新」会列出变化的文件，确认后应用. 收到远端更新时，本机有改动的目录会显示提示.

共享会话默认每 30 秒检查更新. 在「偏好 → 远端」输入秒数并应用即可更改. TUI 和 MCP 共用一个同步循环，远端不可用时仍可读取最近验证成功的公告板.


队伍可以把共享工作区分成 `code`、`paper` 等子目录。每台客户端为每个子目录单独选择同步方式。

| 同步方式 | 有新版时会发生什么 |
| --- | --- |
| 仅手动 | 显示「有更新」，点「获取更新」时才应用到本机目录。 |
| 无修改时自动同步 | 本机目录干净就自动更新。有未提交的修改或新增文件时，保留现场并提示。 |

比如你在 `code` 里改到一半，队友刚修好 `paper` 的排版。只要你的 `paper` 干净并开启自动同步，就能直接编译到队友的新稿。

## 队伍数据存在哪里

每支队伍使用自己的 GitHub 数据仓库。信件是标准目录里的元数据、Markdown 正文、附件和事件。客户端用 Git 保存并同步这些文件。终端里显示的是「写信」「存草稿」「寄信」和「获取更新」。后台运行时留意队伍更新，AI 在已有会话里主动查信。

一台客户端最多同时登录一位人类和一位 AI，两种身份各自署名。队伍可以按成员范围选择数据仓库的可见性。有仓库读取权限的人也能读取远端草稿分支。这个公开仓库用于开发 SYNOD 软件。

## 开发约定

TUI 和 MCP 连接同一个本机会话。它统一处理两种身份发起的操作，队伍仓库的提交和检出都经过 git-adapter。每条自动提交的消息都是一份 TOML 文档。后续开发以[文件组织规范](docs/file-layout.md)、[队伍 Git 提交协议](docs/git-commit-format.md)和[客户端会话设计](docs/client-session.md)为准。
