# SYNOD

SYNOD 是为竞赛小队设计的终端协作工具。三位队员各带一位 AI 助手，六个成员都有自己的收件地址。你可以给队友寄信，也可以直接把任务交给队友的助手。人使用 **Rust + Ratatui** 的交互终端，助手通过 **MCP** 收信和办理任务。

项目目前处于初始设计阶段。下面用一场比赛里的交接说明预期体验。目录格式、并发规则和验收场景见[初始设计蓝图](docs/initial-design.md)。

## 把图 3 交给 Alice

你负责模型，Alice 负责画图。你点「写信」，标题填《重画图 3》，附上绘图要求，再把《交付模型结果 v2》选为前置依赖。

1. **存草稿。** 看到「草稿已存至云端」，就可以换一台电脑接着写。Alice 的收件箱此时只列已经寄出的信。
2. **寄信。** 看到「已寄出」后，Alice 下次同步就能读到原文和附件。只要模型结果还没交付，她就能看到自己正在等哪封信。
3. **完成。** Alice 画好图，在原信上勾选「任务完成」。你这里自动同步后，看到同一封信上的勾。整个操作只要点一下。

```text
《重画图 3》                     ☑ 任务完成
发件人  你                       收件人  Alice
依赖    《交付模型结果 v2》       进度    100%
```

这个勾选会留下一条有署名和时间的**事件**。以后打开信件历史，就能看到「Alice 于 15:42 将任务标记为已完成」。如果接手画图的是 Alice 的助手，它可以在自己的会话里通过 MCP 做同样的操作，用自己的身份署名。

## 代码和论文各自同步

队伍可以把共享工作区分成 `code`、`paper` 等子目录。每台客户端为每个子目录单独选择同步方式。

| 同步方式 | 有新版时会发生什么 |
| --- | --- |
| 仅手动 | 显示「有更新」，点「获取更新」时才应用到本机目录。 |
| 无修改时自动同步 | 本机目录干净就自动更新。有未提交的修改或新增文件时，保留现场并提示。 |

比如你在 `code` 里改到一半，队友刚修好 `paper` 的排版。只要你的 `paper` 干净并开启自动同步，就能直接编译到队友的新稿。

## 队伍数据存在哪里

每支队伍使用自己的 GitHub 数据仓库。信件是标准目录里的元数据、Markdown 正文、附件和事件。客户端用 Git 保存并同步这些文件。终端里显示的是「写信」「存草稿」「寄信」和「获取更新」。后台运行时留意队伍更新，AI 在已有会话里主动查信。

一台客户端最多同时登录一位人类和一位 AI，两种身份各自署名。队伍可以按成员范围选择数据仓库的可见性。有仓库读取权限的人也能读取远端草稿分支。这个公开仓库用于开发 SYNOD 软件。
