# 同一客户端的共享会话

蓝图 0.3 · 已评审的 TUI 与 MCP 同机运行约定

## 启动一次，两种入口连接

同一操作系统用户下，规范化后相同的客户端状态根对应**一个会话宿主进程**。`synod` 打开 TUI，`synod mcp` 作为 AI 宿主的标准输入输出桥。两者先寻找同一个本地端点。第一个入口可启动会话，后来的入口直接连接。每台队员设备各自运行会话，通过队伍 Git 仓库同步。

```text
synod (Ratatui) ───────────┐
                          ├── local IPC ── session host ── application ── git-adapter
AI host ── synod mcp ─────┘                                 └────────── local files
```

会话持有一对独立身份位、同一份队伍视图、一个待投递队列和一个后台同步循环。本机 IPC 的信任边界是当前系统用户。握手将 TUI 连接绑定到已登录的人类位，将 MCP 连接绑定到已登录的助手位。署名由会话从连接上下文取得。换账号后，已经入队的动作仍带原身份和队伍。MCP 进程的标准输出专用于宿主协议，客户端后台只同步数据。

## 两个入口同时启动或退出

1. 入口先连接本机端点并握手。端点不可用时可启动候选宿主。候选先取得 `runtime/owner.lock` 的操作系统排他锁，持锁者负责恢复待投递队列并发布就绪端点。其他候选退出，入口限时等候就绪后连接。真正的所有者由系统锁决定。
2. `endpoint.json` 用原子替换公布协议版本、会话代次和本机地址。Unix 在当前用户的私有短路径下使用域套接字，Windows 使用限当前用户的命名管道。连接时核对代次和协议版本。锁文件使用固定路径和同一文件对象，所有者持锁期间保持其存在。崩溃释放系统锁，新所有者取得锁后才能替换残留端点。握手版本不兼容时提示升级。
3. 一个入口关闭时释放自己的连接，其他连接继续工作。最后一个入口离开后，宿主停收新动作，完成本地持久化并有序退出。关闭期间的新连接重新发现端点。已接纳但远端结果未知的动作用原编号保留，下次先核对远端。宿主直至关闭监听、收束 Git 子进程并清理自己的端点后才释放所有权锁。

## 两边同时操作同一封信

| 请求 | 会话的处理 |
| --- | --- |
| 查询 | 两个入口读取同一修订号的已发布视图。待同步反馈带有操作编号。发布成功后推进视图，TUI 刷新，助手下次查询得到同一结果。 |
| 提交动作 | 前端为一次写意图分配稳定操作编号，随目标、动作和观察到的版本一起传入，重连重发沿用原编号。会话冻结输入，持久化 outbox 后才确认「已排队」。同队变更按序裁决，同一时刻只执行一个写尝试。并发查询和收取新意图可以继续。 |
| 两边都标记完成 | 先接纳的动作创建 `MarkedCompleted`。第二个动作在新状态上得到「已经完成」。两次点击有各自署名，历史保留实际生效的那一条。 |
| 两边填了不同进度 | 命令携带观察到的上一进度版本。后处理的一方若已过期，保留其输入并显示当前值，供操作者重新决定。 |
| 重连与其他设备抢先 | 本地重试按队伍和操作编号核对冻结意图。远端先收下时直接确认。其他设备先推进主线时重新抓取并校验全队标题、依赖与状态。 |

写队列决定操作次序。耗时的抓取、推送和磁盘准备交给有明确归属的执行任务，结果带会话代次、原操作编号和预期基线回到会话。只有当前代次且仍在途的结果可以推进状态。会话只在短暂本机事务中改变待投递状态与视图，网络等待期间仍可处理查询。后台抓取或外部编辑带来更新时，在应用候选结果前重新核对所依据的主线或文件基线。每个子工作区继续独立判断手动或自动同步。

MCP 的协议请求编号用于对应当前请求与响应。跨连接恢复写操作时使用原操作编号，可按它查询排队或已确认的结果。宿主崩溃后，旧 Git 子进程的远端结果可能尚未确定。新的尝试使用独立工作副本，同一份冻结意图只以普通快进更新远端，遇到引用前进再核对操作身份。草稿或同一子空间中互相依赖的待处理动作依序恢复。

## 验收

用两个独立进程同时从同一状态根首次连接，应得到相同会话代次，并看到一个同步所有者。两端同时完成同一封信后，主线应只有一个生效事件。关闭 TUI 后 MCP 应能继续办理，再次打开 TUI 可查到相同结果。还应覆盖宿主在待投递记录落盘后退出、确认丢失后重连，以及旧端点残留时新所有者的恢复。[目录与恢复数据](file-layout.md)
